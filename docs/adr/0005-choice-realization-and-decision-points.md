# Choice 以探针输出为准，并纳入处置完整性阻断

本 ADR 修订 ADR-0003 第 3 条的硬阻断范围，并补充 ADR-0004 的 Spec 状态转移规则。

## 背景

Spider2 错题分析（2026-09-26）显示，选择类错误并不主要来自"不知道哪个候选对"：

- 运行时不知道一个 Choice 的各候选会不会产生不同的输出，Agent 的探索和裁决精力大量花在不改变结果的歧义上。
- `compare_hypotheses` 接收自由文本候选，运行时无法把建议对应到 Spec 中的 Choice；Agent 可以用无需理由的临时选择（provisional）越过建议的倾向（local028、local031）。
- Choice 的处置结果与结果 SQL 之间没有任何关联；Spec 记录了一个口径，交付的结果却按另一个口径计算，运行时无法察觉。
- 决定结果的计算细节（计数粒度、时间字段、分母等）经常没有被列为候选；运行时看不到这种遗漏。

## 决策

1. **探针（Choice Probe）。** Choice 的每个候选可以绑定一次 exploration 执行，运行时按输出比对规则计算其结果指纹。所有候选指纹相同的 Choice 可以处置为 `equivalent`：由 Agent 提交、运行时核验指纹后接受，不需要理由、建议和披露；视图中标明每个 Choice 的输出是相同、不同还是未知。选定或临时选择一个 Choice 之前，每个候选都必须有探针或声明不可探测的理由。
2. **建议绑定 Choice。** `compare_hypotheses` 只比较一个 Choice 的全部候选。运行时把建议记入受信任的 Advisory Ledger；建议本身仍不是证据，也不能单独处置 Choice。
3. **处置须说明理由，偏离建议须说明依据。** 临时选择与选定一样需要理由。当 Advisory Ledger 对该 Choice 记录了明显倾向而处置结果不是该倾向时，处置必须附带偏离理由和至少一条已准入证据。
4. **处置须在结果中兑现。** 结果查询的指纹若等于某个未被采纳候选的探针指纹、且不等于被采纳候选的指纹，该结果不能成为 Result Candidate。
5. **决策点必须显式声明。** Revision 必须对固定的一组决策点逐项声明"题面已规定（附经核验的题面引文）""不适用""由某 Choice 决定"或"由某 Hypothesis 假定"。仍有未声明的决策点时，Revision 不能进入 Ready，result SQL 与发布被阻断；exploration 不受影响。

## 与 ADR-0003 的关系

ADR-0003 的三类硬阻断保持不变，新增两类，二者都属于"处置生命周期完整性"，不判断哪个口径正确：

- 结果兑现了当前 Revision 未采纳的候选（决策 4）。判断依据是两次确定性执行的指纹是否相等，而不是业务语义。
- 存在未声明的决策点时的 result SQL 与发布（决策 5）。它与"存在 unhandled 假设时阻断"同类：只要求声明，不裁决声明内容。

指纹不可用（探针结果被截断、执行失败、候选声明不可探测）时，按 ADR-0003 记录为 `unavailable` 并披露，不阻断。

## 后果

- 每个 Choice 至少多出与候选数相等的探针查询；不影响输出的 Choice 不再需要裁决和建议调用，可部分抵消成本。
- 在创建 Choice 时直接选定（inline selection）只在全部候选声明不可探测时允许。
- 指纹比对只能发现"结果等于另一个候选"，不能证明"结果等于被采纳候选"；其他 Choice 的处置变化会让旧探针过时，此时兑现检查只能给出 `unavailable`。
- 决策点清单是固定、有限的类目，不覆盖所有可能的歧义；它让遗漏可见，但不保证 Agent 声明正确。

## 修订（2026-10-12）：偏离倾向的证据须能确定该字段

决策 3 的“至少一条已准入证据”收紧为：至少一条证据对该字段合格（ADR-0006 的分层规则）。语义字段上，观测只能说明数据长什么样，不能确立业务含义，因此不能单独推翻建议的倾向；物理字段仍接受观测。依据：2026-10-10 字段树运行中 local066 的 `population.conditions` 候选“按加/去料调整”被建议倾向（0.45 对 0.04），模型仅凭 4 条 `query_observation` 改选“忽略加/去料”，即该题的已证错因。该运行最终 Spec 中只有这一次偏离。

## 修订（2026-10-13）：建议无倾向时交给用户

建议服务作答但没有明显倾向（`[ADVICE_LEAN] none`，如 `multiple_plausible`、`insufficient_evidence`）时，说明原题不能裁决该字段。会话能询问用户时，决定须引用用户的回答或业务文档；原题措辞不算，建议服务已经读过原题。不能询问用户时（如评测关闭澄清），照常决定，Revision 记录 `adviceUndecided`，发布时披露“决定未经裁决”。服务故障（`unavailable`）仍按原规则处理。依据：gold89 运行中 local056 两个候选都已探针，建议为 multiple_plausible（最高 0.24），模型自行选择后答错；local141 的两种金额口径交给 Jev 时概率约 0.55 对 0.45。

## 修订（2026-10-15）：建议由运行时请求；探针只在其他字段不变时有效

**建议由运行时请求。** 决策 2 的 `compare_hypotheses` 工具移除。待定字段的每个候选都有探针或豁免、且输出不全相同时，需要建议是确定的状态，不该再让模型多调一次工具：运行时在补齐输出的那次探针返回时（或豁免补齐时）调用建议服务，把建议记在 Query Task 上，随探针结果和状态表返回；决定前若仍缺建议，`set_answer_spec` 先补问再校验。建议只对它比较过的候选与探针输出有效，输出变化后重新请求。服务故障记为 `unavailable`，一分钟后才重问，决定照常进行并披露。原工具允许模型附带的自由文本 `evidence` 不经准入就交给建议服务，随工具一并取消。决策 2、3 的其余规则（建议不是证据、偏离倾向须附理由与合格证据）不变。Advisory Ledger 不再存在，建议进入 AnsweringStore，随会话持久化。

**探针绑定其他字段的状态。** 后果一节已指出“其他 Choice 的处置变化会让旧探针过时”，但运行时此前仍按旧探针判定等价与决定前提：字段 A 在字段 B 的某个临时取值下各候选输出恰好相同，A 被视为等价；B 改正后 A 的候选可能已不等价，却逃过了决定。现在每个探针记录运行时其他字段的状态与取值（不含依据、理由与候选 ID），其他字段改变后旧探针记为 `stale`：等价判定失效、字段重新待定，决定前须重跑探针。决策 4 的兑现检查仍使用各候选最近一次探针，不论上下文。

## 修订（2026-11-22）：移除 Jev 比较建议与 FieldAdvice

Spider2 同配置对照评测与逐字段回放证明，外部独立模型 Jev 对端到端正确率没有正向贡献，反而增加了一套外部 LLM 配置与运行时状态机复杂度：

- **端到端 A/B（50 道 SQLite 题，`deepseek-flash`）**：实验组不开 Jev 为 **36/50（72%）**（相对控制组 31/50 修复 5 题、回退 0 题）；同一代码的开启 Jev 组（`answering-plan-ab-treatment-jev-002`）为 **34/50（68%）**。在两组均完成的 49 题上，开启 Jev 修复 3 题、弄错 5 题。
- **T4.1 逐字段回放（`evaluations/spider2/jev-witness-replay-v1.json`）**：在 `answering-plan-ab-treatment-jev-002` 产生 Jev 建议的 43 个字段中，仅 19 个能由唯一候选复现 Gold；注入探针差异见证行前后，Jev 选择准确率均为 **14/19（73.7%）**（0 题变对、0 题变错，正确候选平均概率由 0.330 降至 0.307）；在给出明确倾向（`lean: "hypothesis"`）的 10 个字段里，Jev 选错 3 个（`local007`、`local049`、`local201`），当模型缺少推翻倾向的合格证据时反而会锁定错解。

因此彻底移除 Jev 比较建议器及其全部配套机制：

- 删除 `HypothesisChoiceAdvisor`、`JevHypothesisChoiceAdvisor`、`FieldAdvice`（`advice.ts`、`advice-execution.ts`）、`fieldAdvice`、`adviceOverride`、`adviceUnavailable`、`adviceUndecided`、`unadvised`/`undecided` 披露项及 `TYPESAFE_API_KEY` 运行时接线。决策 2 与决策 3 中围绕比较建议与 `adviceOverride` 的约束不再适用。
- **保留全部确定性探针资产**：决策 1 的探针执行、Result Fingerprint、基于当前其他字段上下文的 `stale` 判定与自动 `equivalent` 推导；决策 4 的 `DECISION_NOT_REALIZED` 决定兑现检查；以及探针差异见证行（`[WITNESS]`）在工具视图中的展示。
- 决定待定字段时保留理由要求（`rationale`）与 ADR-0006 统计总体证据约束；能询问用户时统计总体字段仍先取证或澄清，其余无合格证据的决定按未证实记录并在发布时披露。
